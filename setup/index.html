Setup & Fix-it

Read this before you ask for help. Most setup problems in this course are one of the five errors below, and each one has a short fix. Work through the 5-minute check first — it catches nearly all of them before they cost you an evening.

1. The 5-minute setup check

Steps 1–2 each print a version. Steps 3–4 happen in your project folder; step 5 is in your browser.

  1. node --version → expect v26.x. If it shows an older major version (v20, v22), upgrade to Node 26 LTS before starting. If the command is "not found" (Windows says "is not recognized as an internal or external command"), Node is not installed — or the terminal was open before you installed it. Close and reopen the terminal (and VS Code) after installing.
  2. npm --version → expect a number, no error. Windows PowerShell trap: if node works but npm fails with "running scripts is disabled on this system," switch to Command Prompt or Git Bash, or run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned in PowerShell once.
  3. In your project folder: npm install → finishes with no red npm error block. Yellow npm warn lines and a "N vulnerabilities" notice are normal — they do not mean the install failed. Never run npm audit fix --force; it can jump your packages to new major versions.
  4. Start the server: npm start. If that fails with Missing script: "start", your package.json has no start script — run node server.js instead (server.js stands for whatever your entry file is called). Success looks like your listening line — Server running on port 30xx — and the terminal staying busy. If the listening line prints and you immediately get your prompt back, the server is not running: startup failed quietly. See Fix-it #1. While the server runs, that terminal is occupied — open a second terminal for other commands.
  5. Browser: http://localhost:30xx, where your port is 3000 + the last two digits of your student ID. Example: ID ending in 07 → http://localhost:3007; ID ending in 42 → http://localhost:3042. Type http://, not https://. If the browser says "This site can't be reached" (ERR_CONNECTION_REFUSED), either the server is not running (go back to step 4) or the URL's port doesn't match the port your server printed.

Doing the Week 1 homework? Part B runs its own plain-Node server on port 3000; your personal 30xx port is for the Express app in Part D.

3. Fix-it: the errors you will actually hit

#1 EADDRINUSE: address already in use

What it means: a copy of your server is already running on that port — usually the one from your last terminal.

Fix: find the first server's terminal and stop it with Ctrl+C, then start one copy. In Express 5 a taken port can also fail silently: the listening line prints, then the program exits and you get your prompt back. That prompt is the giveaway — in Week 1, where your app holds nothing else open, a running server never gives it back.

Lost the old terminal? End the leftover Node.js process in Task Manager (Windows) or Activity Monitor (Mac), or from a terminal — Mac/Linux: lsof -i :3007 — the PID is in the PID column — then kill 1234 (with that number). Windows, in Command Prompt or PowerShell: netstat -ano | findstr :3007 — the PID is the last number on the line — then taskkill /PID 1234 /F. Use your own port, and don't type the placeholder brackets. (In Git Bash the slashes get rewritten as file paths; use taskkill //PID 1234 //F there, or switch shells.)

The trap: changing the port "fixes" the error but leaves two servers running two versions of your code on two ports, and you no longer know which one the browser is talking to. The bug you then chase is your own stale server.

#2 Form submits, then a 500: Cannot read properties of undefined

You will see errors like Cannot read properties of undefined (reading 'name') or Cannot destructure property 'name' of 'req.body' as it is undefined. Both mean the same thing: your route read req.body, and req.body was undefined because this request's body was never parsed. In Express 5, an unparsed body leaves req.body as undefined — it is not an empty object. That happens when:

  • the body-parsing middleware line is missing, deleted, or commented out;
  • the middleware is registered after the route that reads req.body;
  • the form was sent as GET (no method="POST") — GET data arrives in req.query, not req.body;
  • the body's format doesn't match the parser — form data needs express.urlencoded(); JSON sent by fetch needs express.json().

The line that should be near the top of your app, before your routes:

app.use(express.urlencoded({ extended: true }));

Check: log req.body at the top of the route. undefined = one of the four causes above. An object that is empty, or missing your field, = parsing worked, but the input's name="…" attribute is missing (an id alone doesn't send the value) or spelled differently from what your route reads — name="userName" in the form and req.body.username in the code do not meet. An object with your field names = parsing is fine; look elsewhere.

#3 Browser shows Cannot GET /nope (or Cannot POST …)

What it means: Express reached the end of your routes with no match and answered with its built-in 404 text. This is Express working correctly — there is simply no route for that path and method. A POST to a path you only defined with app.get shows Cannot POST /path; a form with no method="POST" submits as GET and can show Cannot GET even when your app.post route exists. Letter case and a trailing slash don't matter — Express ignores both by default. What matters is the method and the path segments. And if you just added the route, restart the server first (Fix-it #5) — a running server only knows the routes it started with.

Do not copy the old custom-404 pattern

Tutorials written for Express 4 use app.get('*', …). In Express 5 that crashes at startup with a TypeError: Missing parameter name … error (the same happens with '/*'). Custom 404 handling is Week 2 material and uses the Express 5 way.

#4 npm install fails, or the app says a package is missing

Fix sequence:

  1. Confirm you are in the folder that contains package.json (ls / dir should list it).
  2. Read the module name in the error. Cannot find module 'express' = the package isn't installed: if it's listed in package.json, run npm install in the project folder; if it was never added, npm install express installs it and records it. Cannot find module './something' = a local file: check the filename and path in your require/import.
  3. Still stuck? Delete node_modules and run npm install again. Keep package-lock.json — it pins the exact versions you installed; deleting it lets npm pick newer ones and your app quietly changes underneath you.
  4. Only if npm reports a version-not-found (ETARGET) error, check the version range in package.json: ^5.3.0 accepts 5.3.0 up to (not including) 6.0.0; an exact version accepts only itself. (For 0.x versions, ^ allows patch updates only.)

#5 The page loads but your change "doesn't work"

Fix sequence, in this order:

  1. Is the file saved? An unsaved editor tab (look for the dot on the tab) is the most common cause of all.
  2. Did you restart the server? Your server never reloads when you save — however you started it (npm start or node server.js), it is still running the code from when it started. Stop it with Ctrl+C and run it again — or start it as node --watch server.js so Node restarts it for you.
  3. Does the browser URL's port match the port your current server printed?
  4. Hard-refresh the browser (Ctrl+Shift+R; on Mac, Cmd+Shift+R) — cached JS/CSS is the next suspect.
  5. Only then re-read the code.

4. Before you ask for help

Include these six things — they are what any answer will ask for first:

  1. The exact command you ran
  2. The full error text, copied as text (not a photo of your screen)
  3. Your operating system (Windows or Mac) and your Node version (node --version)
  4. The exact URL and method (GET or POST) you tried
  5. The code for the route involved
  6. What you expected to happen instead
